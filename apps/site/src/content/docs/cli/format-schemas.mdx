---
title: Vault format schemas
description: Provider file shapes, field mappings, validation rules, and known import/export limits for every vaultlint format.
---

This reference describes the unencrypted input accepted by each `@vaultlint/vault-formats` adapter. Format identifiers match the `VaultFormatId` values in the package API. Detection uses provider signatures and, for structured JSON, Zod schemas. Provider exports vary by app version; optional and unknown provider fields are retained where the adapter can represent them.

All inputs are converted to the canonical `VaultData` model. The authoritative TypeScript declarations are in [`packages/vault-schema/src/index.ts`](https://github.com/robertbaker/vaultlint/blob/main/packages/vault-schema/src/index.ts).

## Canonical schema

| Object                 | Fields                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `VaultData`            | `{ encrypted?: boolean; folders?: VaultFolder[]; collections?: VaultCollection[]; items: VaultItem[]; [key: string]: unknown }`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `VaultFolder`          | `{ id: string; name: string }`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `VaultCollection`      | `{ id: string; name: string; organizationId?: string; externalId?: string \| null }`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `VaultItem`            | `id?: string`, `name?: string`, `type?: number`, `folderId?: string \| null`, `collectionIds?: (string \| null)[] \| null`, `favorite?: boolean`, `reprompt?: number`, `notes?: string`, `organizationId?: string \| null`, `creationDate?: string \| null`, `deletedDate?: string \| null`, `lastModified?: string`, `revisionDate?: string \| null`, `passwordHistory?: { password: string; lastUsedDate: string \| null }[]`, `secureNote?: { type: number }`, `login?: VaultLogin`, `card?: VaultCard`, `identity?: VaultIdentity`, `fields?: VaultCustomField[]`, `_providerData?: Record<string, unknown>`, and provider extensions. |
| `VaultLogin`           | `username?: string`, `password?: string`, `uris?: VaultUri[]`, `totp?: string`, `fido?: unknown`, `fido2Credentials?: VaultFido2Credential[] \| null`, and provider extensions. `VaultUri` is `string \| { uri: string; match?: number \| null }`.                                                                                                                                                                                                                                                                                                                                                                                         |
| `VaultFido2Credential` | Optional string properties: `credentialId`, `keyType`, `keyAlgorithm`, `keyCurve`, `keyValue`, `rpId`, `counter`, `discoverable`, `userHandle`, `userName`, `rpName`, `userDisplayName`; `creationDate?: string \| null`; provider extensions.                                                                                                                                                                                                                                                                                                                                                                                             |
| `VaultCard`            | Optional string properties: `cardholderName`, `brand`, `number`, `expMonth`, `expYear`, `code`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `VaultIdentity`        | Optional string properties: `title`, `firstName`, `middleName`, `lastName`, `username`, `company`, `email`, `phone`, `address1`, `city`, `state`, `postalCode`, `country`, `ssn`, `passportNumber`, `licenseNumber`; `address2?: string \| null`, `address3?: string \| null`; provider extensions.                                                                                                                                                                                                                                                                                                                                        |
| `VaultCustomField`     | `{ name: string; value: string; type?: number; linkedId?: number \| null }`. The numeric `type` is provider-specific.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |

The common numeric item types are `1` login, `2` secure note, `3` payment card, and `4` identity. Adapters can retain provider-only fields in `_providerData` or named custom fields when those have a stable canonical representation. Importers reject encrypted input.

## JSON and archive formats

| ID                | Accepted root / signature                                                                                                                                                                                                                                                                                  | Field mapping and details                                                                                                                                                                                                                                                                                                                                                                                      |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bitwarden-json`  | Object with `items: []`; optional `folders`, `collections`, `encrypted`. Item fields include `type`, `name`, `notes`, `login`, `card`, `identity`, and `fields`.                                                                                                                                           | Login URIs, username, password, TOTP, cards, identities, folders, and custom fields map to canonical fields. `encrypted: true` is rejected. Unknown root and item keys are tolerated.                                                                                                                                                                                                                          |
| `dashlane-json`   | Object with `AUTHENTIFIANT: []`; optional `NOTE: []`. Login entries may include `title`, `domain`, `login`, `secondaryLogin`, `email`, `password`, `note`, `otpSecret`, and `category`.                                                                                                                    | Domain becomes a URI; login/email/secondary login, password, OTP, notes, and category are mapped. Secure notes use `title`, `content`, and `category`. Unknown provider keys are tolerated.                                                                                                                                                                                                                    |
| `enpass-json`     | `{ "items": [...], "folders": [...] }`. An item can have `uuid`, `title`, `note`, `template_type`, `fields`, folder UUIDs, `trashed`, `archived`, timestamps, and `attachments`. Fields carry `type`, `label`, `value`, `sensitive`, and `deleted`. Folder entries use `uuid`, `parent_uuid`, and `title`. | Login/password, URL, email, TOTP, payment-card fields, custom fields, folder hierarchy, archive state, and Unix-second timestamps are mapped. Deleted/section/blank fields are ignored; trashed records are omitted with a warning. Attachments are not imported. Zod accepts string or numeric field values and boolean or numeric flags.                                                                     |
| `keeper-json`     | Object with `records: []`; optional `shared_folders`. Records may include `title`, `login`, `password`, `login_url`, `notes`, `custom_fields`, `folders`, `fields`, and `$type`.                                                                                                                           | `$type` values `login`, `note`, and `paymentCard` are mapped. TOTP and custom fields are read from `custom_fields`; card values are read from the `fields[].value[]` objects. Folder paths are flattened. Unknown fields are tolerated.                                                                                                                                                                        |
| `protonpass-json` | Object with provider `vaults` map; each vault can contain `name`, `items`, and `folders`. Also accepted from the unencrypted Proton ZIP at `Proton Pass/data.json`.                                                                                                                                        | Login, URL, TOTP, notes, custom fields, and folder data are mapped. `encrypted: true` is rejected. Optional object keys are tolerated.                                                                                                                                                                                                                                                                         |
| `1password-1pux`  | ZIP archive containing `export.data`, or the JSON contents of `export.data` directly. Root is `{ accounts: Account[] }`; accounts contain vaults and vaults contain items.                                                                                                                                 | Vaults become folders; item category, title, URLs, credentials, notes, sections/custom fields, dates, and password history are mapped. Recognized credit-card and identity labels populate canonical fields while remaining custom fields preserve scalar source values. Tags, archive status, and FIDO2 credentials are not represented. ZIP entry and JSON container structure are validated before parsing. |

JSON Zod schemas allow provider extensions where the format uses `.passthrough()`, while checking required arrays and field types used by the parser. A schema match is a structural check, not a guarantee that every provider-specific feature is preserved by the canonical model.

## CSV formats

CSV headers are matched case-insensitively after trimming. CSV parsers support quoted cells, commas, and embedded line breaks according to the provider adapter. Optional columns may be absent unless noted.

| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bitwarden-csv`  | Requires `login_uri`, `login_username`, `login_password`; personal and organization export columns are described below.                                                                                                 | Login values, URI, TOTP, notes, folder/collection, type, and additional fields are mapped.                                                                                                                       |
| `lastpass-csv`   | Requires `url`, `username`, `password`, `extra`, `grouping`, `fav`; optional `name`, `totp`.                                                                                                                            | Login data, notes, group/folder, favorite and TOTP are mapped.                                                                                                                                                   |
| `1password-csv`  | Requires `Title`, `Username`, and `Password`, plus one recognized signature: `OTPAuth`, `Favorite`, `Tags`; or `Url`; or `Website`. Header matching is case-insensitive.                                                | Login credentials, URLs, notes, favorite, TOTP, and tags are mapped when present. CSV cannot represent all 1Password item categories.                                                                            |
| `keepass-csv`    | KeePass CSV headers including `Group`, `Title`, `Username`, `Password`, `URL`, `Notes`.                                                                                                                                 | Standard KeePass CSV login columns and groups are mapped. CSV files are unencrypted.                                                                                                                             |

| `nordpass-csv`   | Requires `name`, `url`, `username`, `password`, `cardholdername`, and `folder` (supports optional `note`, card, identity, `type`, `totp`, and `shared_folder` columns).                                                 | Login, TOTP, notes, folder, payment-card columns, and identity columns are mapped when present.                                                                                                                  |
| `enpass-csv`     | Enpass login template: `Title`, `Username`, `Email`, `Password`, `Website`, `TOTP Secret Key`, `Custom Field 1`, `*Custom Field 2`, `Note`, `Tags`.                                                                     | This template is for login items. | `chrome-csv`     | Chromium browser CSV: `name`, `url`, `username`, `password`; Chrome, Edge, and Brave variants are recognized.                                                                                                           | Browser credentials map to logins.                                                                                                                                                                               |
| `firefox-csv`    | `url`, `username`, `password`, `httpRealm`, `formActionOrigin`.                                                                                                                                                         | Browser credentials map to logins, using available URL columns.                                                                                                                                                  |
| `safari-csv`     | `Title`, `URL`, `Username`, `Password`; accepts Safari/macOS Passwords CSV capitalization variants.                                                                                                                     | Browser credentials and URL map to logins.                                                                                                                                                                       |

### JSON structural field contracts

These describe the fields inspected by the adapters. `?` means optional; a nullable field may be absent or explicitly `null`. Schemas allow additional properties where the provider format is extensible. Detailed mapping behavior and known losses remain in the JSON table above.

| ID                | Root contract                                                                                                               | Record contract                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bitwarden-json`  | `{ items: object[], folders?: object[], collections?: object[], encrypted?: boolean, ... }`. `encrypted: true` is rejected. | Folder: `id`, `name` strings. Collection: `id`, `name` strings and optional `organizationId`. Item: optional string `id`, `name`, `organizationId`, `creationDate`, `revisionDate`; numeric `type`; boolean `favorite`; `login` object with string `username`, `password`, `totp`, and `uris` of strings or `{ uri: string }` objects; `fields[]` of `{ name?: string, value?: string, type?: number }`; `passwordHistory[]` objects; and string/null `collectionIds`. Unknown properties pass through. |
| `dashlane-json`   | `{ AUTHENTIFIANT?: object[], NOTE?: object[], ... }`; parser requires `AUTHENTIFIANT` to be an array.                       | Login entries: optional string `title`, `domain`, `login`, `secondaryLogin`, `email`, `password`, `note`, `otpSecret`, `category`. Note entries: optional string `title`, `content`, `category`. Known fields allow `null`; unknown properties pass through.                                                                                                                                                                                                                                            |
| `enpass-json`     | `{ items: EnpassItem[], folders?: EnpassFolder[] }`. `items` is required.                                                   | Item: optional nullable string `uuid`, `title`, `note`, `template_type`; `fields[]`; string[] `folders`; numeric/boolean flags `trashed`, `archived`; numeric Unix-second `createdAt`, `updated_at`; unknown `attachments[]`. Field: optional nullable string `type`, `label`; nullable string/number `value`; nullable numeric/boolean `sensitive`, `deleted`. | `keeper-json`     | `{ records: KeeperRecord[], shared_folders?: { path: string, ... }[] }`.                                                    | Record: optional nullable strings `title`, `login`, `password`, `login_url`, `notes`, `$type`; `custom_fields` string-keyed object; `folders[]` string-valued objects; `fields[]` of objects with optional nullable string `type` and required `value` of any JSON type. | `protonpass-json` | `{ encrypted?: boolean, vaults: Record<string, ProtonVault>, ... }`; `vaults` is required. `encrypted: true` is rejected.   | Vault: optional nullable string `name`; optional `items[]` and `folders[]` (entries are validated by the importer, not constrained by the root Zod schema); additional vault/root properties pass through. #### Proton Pass item shape

The root Zod schema constrains each vault's `items` and `folders` properties to arrays but leaves their contents open for provider-version compatibility. The adapter reads these record fields when present:

| Path                      | Recognized fields                                                                                                                                               |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `item`                    | `itemId?: string`, `state?: number`, `modifyTime?: number`, `createTime?: number`, `folderId?: string \| null`, `aliasEmail?: string`, `pinned?: boolean`.      |
| `item.data`               | `type?: string`, `metadata?: { name?: string; note?: string }`, `content?`, `extraFields?`; unknown fields are kept on the provider payload for JSON re-export. |
| `item.data.content`       | `username`, `itemUsername`, `email`, `itemEmail`, `password`, `urls?: string[]`, `totpUri`, `autofillUrls?: { url: string; mode?: number }[]`.                  |
| `item.data.extraFields[]` | `fieldName?: string`, `type?: string`, `data?: { content?: string; totpUri?: string; timestamp?: number }`.                                                     |
| `vault.folders[]`         | `folderId: string`, optional nullable `parentFolderId`, `name: string`. Nested folders are flattened during import.                                             |

#### 1Password 1PUX item shape

The adapter reads the following fields from each vault item's `overview` and `details` objects. Entries not listed here may remain in the raw archive during parsing but are not represented in canonical output.

| Path                      | Recognized fields                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `item`                    | `uuid?: string`, `favIndex?: number`, `state?: string`, `createdAt?: number`, `updatedAt?: number`, `categoryUuid?: string`.                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `item.overview`           | `title?: string`, `url?: string`, `urls?: { url?: string; label?: string }[]`, `tags?: string[]`, `subtitle?: string`.                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `item.details`            | `loginFields?: { id?: string; name?: string; fieldType?: string; value?: string; designation?: string }[]`, `notesPlain?: string`, `password?: string`, `sections?: Section[]`, `passwordHistory?: { value?: string; time?: number }[]`.                                                                                                                                                                                                                                                                                                            |
| `item.details.sections[]` | `title?: string`, `name?: string`, `fields?: { id?: string; title?: string; value?: string \| { totp?: string; string?: string; concealed?: string; creditCardNumber?: string; creditCardType?: string; monthYear?: string; ... } }[]`. Recognized scalar card labels include cardholder name, card type, card number, expiration, and security code. Recognized scalar identity labels include personal name, company, contact, address, and document number fields. These values also remain custom fields when mapped into `card` or `identity`. |

## KeePass XML

`keepass-xml` accepts unencrypted KeePass 2.x XML with a `KeePassFile/Root/Group` hierarchy. Entry `String` pairs map standard `Title`, `UserName`, `Password`, `URL`, and `Notes` keys; nested groups become folders. Custom string keys are retained as custom fields. Password-protected KDBX databases are not parsed.

## Validation and encrypted exports

Zod validates the JSON roots and container shapes described above; Bitwarden additionally checks nested record fields before accepting the export. Proton Pass and 1Password validate their root/container structure while their provider records are interpreted by the adapters. CSV detection uses case-insensitive header signatures; Dashlane and RoboForm also validate their provider-specific header shapes and RoboForm rows with Zod. Unknown JSON keys and CSV columns are accepted where possible, since providers add fields over time.

Encrypted Bitwarden and Proton Pass JSON exports are rejected. KeePass `.kdbx` files and Bramble `.bramble` backups are encrypted and are not supported. Bramble's KeePass export is also password-protected: open it in KeePassXC and export as CSV or KeePass XML before importing it into vaultlint. See the [Bramble export documentation](https://bramble.sh/docs/export-your-vault).

## Using the format API

`VAULT_FORMATS` lists adapter metadata (`id`, display name, provider, extensions, MIME type, and description). `parseVault` accepts text, bytes, or a parsed JSON object; pass `{ format }` to select an adapter explicitly and `{ fileName }` to preserve extension-based detection and encrypted-file errors. Use `parseVaultAsync` for ZIP archives in browser environments. Parsing returns the canonical vault, the detected format ID, provider/format names, and import warnings. `exportVault` takes the canonical vault and a target format ID and returns the file content, MIME type, extension, and export warnings.

```ts
import { exportVault, parseVaultAsync, VAULT_FORMATS } from "@vaultlint/vault-formats";

const bytes = new Uint8Array(await file.arrayBuffer());
const parsed = await parseVaultAsync(bytes, { fileName: file.name });
const converted = exportVault(parsed.vault, "enpass-json");
console.log(VAULT_FORMATS.map(({ id, name }) => ({ id, name })));
```

See [supported formats](../formats/) for the concise matrix and conversion examples.
